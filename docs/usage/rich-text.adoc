= Rich text
:imagesdir: ../images

Guillotine exposes HtmlArea fields as the <<../api#richtext, RichText>> type, with raw and processed HTML plus structured information about links, images and macros.

The examples use the `myproject` project and an illustrative `com.example.myapp:post` content type. Replace the project, content paths, generated type names and form fields with those shown in your <<../playground#, Playground>> schema. Send these queries using the request format on the <<../usage#, Usage>> page.

== Processed HTML

Retrieve blog posts with an author reference, tags and an HtmlArea field named `text`:
[source,graphql]
----
{
  guillotine(project: "myproject", branch: "master") {
    queryDsl(
      query: {
        term: {
          field: "type"
          value: { string: "com.example.myapp:post" }
        }
      }
      first: 10
    ) {
      ... on com_example_myapp_Post {
        data {
          author {
            displayName
          }
          tags
          text {
            processedHtml
          }
        }
      }
    }
  }
}
----

`processedHtml` contains HTML with placeholders for internal links, images and macros. The structured fields described below hold what your client needs to render them.

Link and image placeholders are readable values, useful for debugging: a page link shows the content path, a media link the media API path. Browsers cannot follow them as they are. Render each one by rewriting the element that carries a `data-link-ref` or `data-image-ref` attribute from its entry in `links` or `images`.

== Links

Each internal link receives a `data-link-ref` attribute naming its entry in the `links` field, and an `href` placeholder:

* a page link shows the content path relative to the site selected with `siteKey`, with the query and fragment the link carries, such as `/posts/first-post?ref=news#intro`; the site itself shows `/`, while its `pageUrl.path` is empty, as for <<images-and-urls#base-urls, the selected site>>. Without `siteKey`, it shows the full content path, such as `/my-site/posts/first-post`;
* a media link shows the media API path, such as `/media:attachment/...`.

Build the `href` from the link's entry. For a page link, use `pageUrl`: `baseUrl` is the Base URL configured for the selected site, or for the project without `siteKey`, `null` when there is none, followed by `path` and `queryString`, or adapt `path` to your frontend's routes. Sites do not inherit a Base URL from their parent; see <<images-and-urls#base-urls, Base URLs>>. For a media link, put your media base in front of `media.mediaUrl.path` and `media.mediaUrl.queryString`.

For instance, the processed value of a link looks like this:

[source,html]
----
<p>
    <a title="Tooltip"
        href="/posts/related-post"
        data-link-ref="e72f48b6-a972-4133-a300-a3ab5d132800">Link 1</a>
</p>
----

The GraphQL query below will process links inside the field:

[source,graphql]
----
query {
  guillotine(project: "myproject", branch: "master", siteKey: "/my-site") {
    get(key: "/my-site/posts/first-post") {
      ... on com_example_myapp_Post {
        data {
          text {
            links {
              ref          # <1>
              uri          # <2>
              media {      # <3>
                content {
                 _id
                }
                intent     # <4>
                mediaUrl {
                  path
                  queryString
                  context
                  id
                  fingerprint
                  name
                }
              }
              content {    # <5>
                _id
              }
              pageUrl {    # <6>
                baseUrl
                path
                queryString
              }
            }
          }
        }
      }
    }
  }
}
----
<1> Reference to link in the `processedHtml` field
<2> Link URI
<3> Related media content and the components of the attachment URL, including its segments; see <<images-and-urls#url-segments, Building URLs from segments>>. This field has `null` value for non-media content
<4> Link intent. Available values `download` and `inline`
<5> Related content. This field has `null` value for media content
<6> Components of the page URL, with the query string the link carries, relative to the site selected with `siteKey`, or to the project without it. `baseUrl` is the Base URL configured there, or `null`. This field has `null` value for media links

== Images

Each internal image receives a `data-image-ref` attribute naming its entry in the `images` field, and `src` and `srcset` placeholders showing the media API path, such as `/media:image/...`.

Build the image URLs from the image's entry, which holds one URL for each attribute:

* `src` is a single <<../api#imageurl, ImageUrl>>: the image for the `src` attribute, 768 pixels wide, or cropped to the style's aspect ratio. An image the image API serves as stored has the `full` scale and no filter.
* `srcset` is a list of <<../api#imagesource, ImageSource>> entries, one for each width requested with `processHtml.imageWidths`. It is empty without them, and for an image the image API serves as stored, whatever its width: such an image has its `src` alone. Each entry holds the `width`, used as the `w` descriptor, and an `imageUrl` of the same image scaled to that width.

Put your media base in front of each `path` and `queryString`. See <<../configuration#media-base-url, Media base URL>>.

The style of an image is the one named in the HtmlArea, looked up among the styles of the applications configured on the site selected with `siteKey`, or on the project without it.

For instance, the processed value of an image looks like this:

[source,html]
----
<figure class="editor-align-justify">
    <img alt="Alt text"
         src="/media:image/myproject/contentid:fingerprint/width-768/photo.jpg"
         data-image-ref="4f2439ff-ecef-4470-a4b4-d8929bce6ee2" />
    <figcaption>Caption text</figcaption>
</figure>
----


The query below will process images inside the field:

[source,graphql]
----
query {
  guillotine(project: "myproject", branch: "master") {
    get(key: "/my-site/posts/first-post") {
      ... on com_example_myapp_Post {
        data {
          text {
            images {
              ref                           # <1>
              image {                       # <2>
                ... imageFragment
              }
              style {                       # <3>
                name
                aspectRatio
                filter
              }
              src {                         # <4>
                path
                queryString
                context
                id
                fingerprint
                scale
                name
              }
              srcset {                      # <5>
                width
                imageUrl {
                  path
                  queryString
                }
              }
            }
          }
        }
      }
    }
  }
}

fragment imageFragment on Content {
  _id
  type
  ... on media_Image {
    data {
      caption
    }
  }
  ... on media_Vector {
    data {
      caption
    }
  }
}
----
<1> Reference to an image in the `processedHtml` field
<2> Image as <<../api#content, Content>> type
<3> Image style as <<../api#imagestyle, ImageStyle>> type
<4> Components of the `src` URL, with the style's scale and filter applied, including its segments; see <<images-and-urls#url-segments, Building URLs from segments>>
<5> Components of each `srcset` URL, one for each of the `imageWidths`; empty without them, and for an image served as stored

Use the `processHtml` argument, of type <<../api#processhtmlinput, ProcessHtmlInput>>, on an HtmlArea field to control image processing. Setting `imageWidths` adds a `srcset` with an entry for each requested width to the image tags of images the image API scales.

For example:

[source,graphql]
----
{
  guillotine(project: "myproject", branch: "master") {
    get(key: "/my-site/posts/first-post") {
      ... on com_example_myapp_Post {
        data {
          text(processHtml: { imageWidths: [600, 992] }) {
            processedHtml
            images {
              ref
              src {
                path
                queryString
              }
              srcset {
                width
                imageUrl {
                  path
                  queryString
                }
              }
            }
          }
        }
      }
    }
  }
}
----

The processed HTML holds both attributes as placeholders:

[source,html]
----
<figure class="editor-align-justify">
    <img alt="Alt text"
         src="/media:image/myproject/contentid:fingerprint/width-768/photo.jpg"
         data-image-ref="4f2439ff-ecef-4470-a4b4-d8929bce6ee2"
         srcset="/media:image/myproject/contentid:fingerprint/width-600/photo.jpg 600w,
                 /media:image/myproject/contentid:fingerprint/width-992/photo.jpg 992w"/>
    <figcaption>Caption text</figcaption>
</figure>
----

and the image's entry holds their parts: `src` once, `srcset` once for each width:

[source,json]
----
{
  "ref": "4f2439ff-ecef-4470-a4b4-d8929bce6ee2",
  "src": {
    "path": "/media:image/myproject/contentid:fingerprint/width-768/photo.jpg",
    "queryString": ""
  },
  "srcset": [
    {
      "width": 600,
      "imageUrl": {
        "path": "/media:image/myproject/contentid:fingerprint/width-600/photo.jpg",
        "queryString": ""
      }
    },
    {
      "width": 992,
      "imageUrl": {
        "path": "/media:image/myproject/contentid:fingerprint/width-992/photo.jpg",
        "queryString": ""
      }
    }
  ]
}
----

The client rewrites both attributes of the element from the entry:

[source,javascript]
----
const mediaBaseUrl = 'https://example.com/api';
const url = (u) => mediaBaseUrl + u.path + u.queryString;

const img = document.querySelector(`[data-image-ref="${image.ref}"]`);
img.src = url(image.src);
if (image.srcset.length) {
  img.srcset = image.srcset.map((source) => `${url(source.imageUrl)} ${source.width}w`).join(', ');
}
----

== Macros

Each macro will be translated to an `editor-macro` tag with `data-macro-ref` and `data-macro-name` attributes in the `processedHtml` field value. Using these references you will be able to find details of a specific macro in the `macrosAsJson` or `macros` fields and implement custom macro processing if needed.

[NOTE]
====
Guillotine processes macros which have a descriptor and built-in macros called `disable` and `embed`, otherwise processing will be skipped. https://developer.enonic.com/docs/cms/stable/richtext/macros[More details about macros].
====

For instance, we have an input form item called `description` of `HtmlArea` type which contains the `embed` macro as shown below:

image::embed-macro.png[Embed Macro]

The query below will fetch data for the `description` field:

[source,graphql]
----
query {
  guillotine(project: "myproject", branch: "master") {
    get(key: "/my-site/posts/first-post") {
      ... on com_example_myapp_Post {
        data {
          description {
            raw            # <1>
            processedHtml  # <2>
            macrosAsJson   # <3>
            macros {       # <4>
              ref
              name
              descriptor
              config {
                embed {
                  body
                }
              }
            }
          }
        }
      }
    }
  }
}
----
<1> Non-processed value of the `description` field
<2> Processed value of the `description` field
<3> Array of processed macros in JSON format. The order of macros will be the same as in the `raw` and `processedHtml` fields.
<4> <<../api#macro, Macro>> allows to specify necessary fields. That field is an alternative for `macrosAsJson` field

Results of the query:

image::embed-response-example.png[Response for embed macro]

Custom macros use a https://developer.enonic.com/docs/cms/stable/richtext/macros#descriptor[macro schema] to define their parameters. For example, a `testmacro` macro with a `+default_text+` input is declared at `/cms/macros/testmacro/testmacro.yaml`, relative to the app resource root. In a Gradle project, this is `src/main/resources/cms/macros/testmacro/testmacro.yaml`.

[source,yaml]
----
kind: Macro
title:
  text: Current user
description:
  text: Shows the currently logged-in user
form:
  - type: TextLine
    name: default_text
    label: Text to show if no user is logged in
----

Select `+default_text+` to retrieve the macro parameter defined by this schema:

[source,graphql]
----
query {
  guillotine(project: "myproject", branch: "master") {
    get(key: "/my-site/posts/first-post") {
      ... on com_example_myapp_Post {
        data {
          description {
            macros {
              ref
              name
              descriptor
              config {
                testmacro {
                  default_text
                }
              }
            }
          }
        }
      }
    }
  }
}
----
