== Object Types
=== Query

==== Fields
|===
|Name(Arguments):Type | Description

|guillotine(project: String, branch: String, siteKey: String): <<HeadlessCms>>
a|Type gathering all content retrieval requests

* `project` - name of the content project to query. Default is the project of the request context
* `branch` - branch to query, `draft` or `master`. Default is the branch of the request context
* `siteKey` - ID or path of a site (or `/` for the project root) used as the site context: it resolves the `${site}` placeholder in keys, the `getSite` field, and the base URL of `pageUrl`, media URLs and links in processed HTML from the site's configured Base URL. The query fails if no content matches the key

NOTE: When the request already runs in a project and branch context, i.e. when the API is mounted in a site or invoked from Content Studio, the `project` and `branch` arguments are ignored.
|===

=== HeadlessCms

Gathers all content retrieval requests.

==== Remarks

* Most requests expect a key as an argument. If the key is not specified, then the matched content will be the site given by the `siteKey` argument of the `guillotine` field
* Keys may contain the `${site}` placeholder, which is replaced with the path of the site given by `siteKey`

=== Content

The `Content` interface is implemented by both built-in and custom defined content types. All content types are dynamically generated based on the installed schemas.

All types implementing `Content` share the same fields, with the exception of the `data` field, which offers a specific implementation per type.

=== media_Image

In addition to the fields of the <<Content>> interface, all `media:*` content types provide the field `mediaUrl`, and contents of type `media:image` additionally provide the field `imageUrl`.

==== Fields

|===
|Name(Arguments):Type | Description

|mediaUrl (download: Boolean, params: Json): <<AttachmentUrl>>
|URL to the underlying media attachment, along with its components. Set `download` to `true` to force download instead of inline rendering.

|imageUrl (scale: String!, quality: Int, background: String, format: String, filter: String, params: Json): <<ImageUrl>>
a|URL to a processed version of the image, scaled and cropped by the server at request time, along with its components.

* `scale` (required) - scaling function to apply: `block(width,height)`, `height(height)`, `max(size)`, `square(size)`, `wide(width,height)`, `width(width)` or `full`
* `quality` - compression quality of JPEG images, from 0 to 100. Default is 85
* `background` - background color to use when converting images with transparency, as a hex value, e.g. `ff0000`
* `format` - image format of the generated URL. Supported formats are `jpg`, `png` and `gif` - other formats, such as `webp` or `avif`, are not supported and the resulting URL will fail with `400 Invalid parameters`
* `filter` - image filters to apply, e.g. `rounded(5);sharpen()`
* `params` - additional query parameters to append to the URL
|===

=== Macro

Dynamic type which contains macro details. By default contains two fields: `disable` and `embed`, other fields will be added dynamically based on macro descriptors for provided `applicationKeys` during schema creation.
Given `applicationKeys` are expected to have the same order as in the site configs. It means that first macro descriptor that was matched will be used to process it.

|Macro descriptor, for instance `app:macroName`

|config: <<MacroConfig>>

|===

=== PageUrl

Page URL and its components, for building the URL from segments: `url = baseUrl + path + queryString`.

|===
|Name (Arguments): Type | Description

|url: String
|The ready-made URL, with the base URL resolved by XP (siteKey-configured Base URL when present, request/context resolution otherwise)

|path: String
|URL-escaped path of the content relative to its nearest site (the full content path when there is no site), with a leading slash. Empty when the content is the site itself

|queryString: String
|URL-escaped query string, prefixed with `?`. Empty when there are no parameters

|===

=== ImageUrl

Image URL and its components, for building the URL from segments: `url = baseUrl + path + queryString`. All component values are URL-escaped as they appear in the URL.

|===
|Name (Arguments): Type | Description

|url: String
|The ready-made URL, with the base URL resolved by XP

|path: String
|The full media API path with a leading slash, ready to append to a base URL: `/media:image/<context>/<id>:<fingerprint>/<scale>/<name>`

|queryString: String
|URL-escaped query string, prefixed with `?`. Empty when there are no parameters

|context: String
|Project context segment: `<project>` on the master branch, `<project>:<branch>` otherwise

|id: String
|Content ID

|fingerprint: String
|Media fingerprint, joined with the id as `<id>:<fingerprint>` in the path

|scale: String
|Processed scale segment (for example `max-300`)

|name: String
|File name segment, with the requested format extension applied

|===
