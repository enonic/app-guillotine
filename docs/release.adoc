= Release Notes

IMPORTANT: Guillotine 9 requires XP 8.1.0 or higher.

== Guillotine 9

=== Features

`Project and branch arguments`::
The `guillotine` field accepts the `project` and `branch` arguments, so a single endpoint serves all content projects and branches.

`URL fields as objects`::
`pageUrl`, `imageUrl`, `mediaUrl` and `attachmentUrl` return the new `PageUrl`, `ImageUrl` and `AttachmentUrl` types. Besides the `url` generated by XP for the current request, they expose URL-escaped components such as `path`, `queryString`, `context`, `id`, `fingerprint`, `scale` and `name`, so URLs can be assembled on any origin as `base + path + queryString`.

`URLs in rich text`::
`Link` in the `RichText` type has a new `pageUrl` field, and `Media` has a new `mediaUrl` field, returning the same URL objects for links and media found in processed HTML.

`Base URLs resolved by XP`::
`siteKey` decides which site - or project, with `/` - page URLs and content links in `processedHtml` belong to. XP resolves both the base URL and the path from that site, so `url = baseUrl + path + queryString` holds for the `pageUrl` field. The base is the Base URL configured on the site, or `/site/<project>/<branch>/<site path>` when none is configured. Media URLs use the Base URL of the site or the `media.defaultBaseUrl` option of `com.enonic.xp.portal.cfg`. A content outside the named site has no page URL, and the field reports an error. Without `siteKey`, URLs on a site mount are generated from the site request with vhost mappings applied, and the matched mapping decides the site they belong to. On the `/api` endpoint they are server-relative and each content belongs to its nearest site. See <<usage#url-resolution, URL resolution>>.

`Content._project` and `Content._branch`::
New fields returning the project and branch a content was fetched from.

`PublishInfo`::
New `time` field exposing the `publish.time` marker of the content. When present, the draft matches the published version. When absent, the draft has unpublished changes. The value itself carries no meaning, see https://developer.enonic.com/docs/code/stable/fundamentals/types#publish-info[PublishInfo] in the XP documentation. `from`, `to`, `first` and `time` are `DateTime` values.

`Resolvers run in the query context`::
Resolvers defined by extensions for fields below the `guillotine` field are executed in the XP context of the project and branch of the query.

=== Breaking changes

`Endpoint`::
The API is exposed as the XP API `com.enonic.app.guillotine:graphql` at `/api/com.enonic.app.guillotine:graphql`. The `/site/<project>/<branch>` endpoints are removed. Project and branch are selected with the `project` and `branch` arguments of the `guillotine` field. The endpoint answers `POST` and `OPTIONS` requests only.

`X-Guillotine-SiteKey header`::
Support for the `X-Guillotine-SiteKey` HTTP header is removed. Use the `siteKey` argument of the `guillotine` field.

`UrlType and the type argument`::
The `type` argument (`server`/`absolute`) is removed from the `pageUrl`, `imageUrl`, `mediaUrl` and `attachmentUrl` fields and from `ProcessHtmlInput`, and the `UrlType` enum is removed. URLs are server-relative unless a Base URL applies, see <<usage#url-resolution, URL resolution>>.

`URL fields return objects`::
`pageUrl`, `imageUrl`, `mediaUrl` and `attachmentUrl` return `PageUrl`, `ImageUrl` or `AttachmentUrl` objects instead of `String`. The `url` subfield is the URL as the corresponding portal library function generates it for the current request, so its value depends on how the API is invoked, see <<usage#url-resolution, URL resolution>>. To build URLs for another origin, use the URL components.

`query and queryConnection`::
The deprecated `query` and `queryConnection` fields of `HeadlessCms`, the `QueryContentConnection` type and the filter input types `FilterInput`, `BooleanFilterInput`, `ExistsFilterInput`, `NotExistsFilterInput`, `HasValueFilterInput` and `IdsFilterInput` are removed. Use `queryDsl` and `queryDslConnection`.

`_path type argument`::
The `type` argument of the `_path` field and the `ContentPathType` enum are removed. `_path` always returns the full content path. Use the `path` component of `pageUrl` for the path relative to the site given as `siteKey`.

`getSite without siteKey`::
`getSite` returns `null` when the `siteKey` argument is not provided, and the `siteKey` property of `localContext` in resolvers is absent instead of `/`.

`ContentType.displayName`::
The `displayName` field, deprecated in Guillotine 8, is removed. Use `title` instead.

`FormInput`::
The `customText`, `validationRegexp`, `maximize` and `defaultValue` fields are removed from `FormInput`, the `customText` field is removed from `FormItemSet`, and the `DefaultValue` type is removed.

`PublishInfo`::
The `from`, `to` and `first` fields are `DateTime` instead of `String`.

`Query Playground`::
The Query Playground is provided as an admin extension implementing the `contentstudio.menuitem` interface. Content Studio embeds it as a panel, as can any application that follows that interface. It is no longer served on the API endpoint, and the `queryplayground.ui.mode` configuration option is removed.
